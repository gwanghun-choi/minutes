# 2026-08-21

## Goal

1. Stop applying database DDL from application startup. Schema becomes an
   explicit deployment step with a recorded version.
2. Make `minutes.users` the source of truth for accounts, replacing the
   environment-variable bootstrap, and give the table the metadata a real login
   needs.

Both are prerequisites for the first NCP deployment of the Productization wave
against a database that already holds real meetings.

## Completed

### Migration runner

- `scripts/migrate.py` — `run()` applies every file in `scripts/migrations/` in
  filename order, exactly once, each inside one transaction with the
  `schema_migrations` row that records it. A failure rolls back and records
  nothing. `verify()` is the read-only startup check.
- `scripts/migrations/001_initial.sql`, `002_productization.sql`,
  `003_user_identity.sql` — the existing schema split along its real history.
  Every statement is `IF NOT EXISTS` or `ADD COLUMN IF NOT EXISTS`.
- `scripts/init_db.sql` deleted; its content lives in `001` and `002` and is not
  duplicated.
- `vector(1024)` is now a literal in `001` rather than a value read from the
  embedding model at apply time, so a migration needs no model to run.

### Startup

- `db.apply_schema()` and `db._plain_conn()` removed. `app/db.py` is a pool,
  `conn()`, and `conninfo()` — it issues no DDL.
- The lifespan is `migrate.verify(dim)` then `db.init_pool()`. `verify` uses a
  standalone connection because on an unmigrated database the pool cannot
  register the `vector` type, and the operator would see a connection error
  instead of the sentence naming the missing migrations.
- pgvector type registration stayed in `db._configure`. It is runtime type
  binding, not DDL, and was deliberately not removed with the schema code.

### DB-managed identity

- `users` gained `display_name`, `is_active`, `updated_at`, `last_login_at`.
  `users.id` remains the internal `BIGINT` key; `users.username` is the login id.
- The POC account `user` / `user1234` is seeded by `003` from a precomputed
  scrypt hash with `WHERE NOT EXISTS`. A re-run never resets a password.
- `auth.bootstrap()` and `config.BOOTSTRAP_USERNAME` / `BOOTSTRAP_PASSWORD`
  removed. No startup code creates a credential.
- `authenticate()` refuses an inactive account and records `last_login_at` on
  success only. `resolve_session()` joins on `u.is_active`, so deactivating an
  account closes the sessions it already handed out.
- The header shows `display_name` with `username` as its tooltip.

## Completed

### Scope dialog

- Root cause: `.modal` sets `display: flex`, an author rule, which outranks the
  browser's own `[hidden] { display: none }`. The `hidden` attribute the script
  toggles therefore did nothing — the dialog was on screen from page load, and
  neither ✕ nor 선택 완료 nor the backdrop could close it. It was never a
  JavaScript bug; every handler was firing.
- One line fixes it: `.modal[hidden] { display: none; }`.
- ✕, the backdrop, and ESC now share one `closeScope()`. 선택 완료 applies the
  scope **after** the PATCH succeeds and shows the error in the dialog if it
  does not — before, `scope` was assigned before the request, so a failure left
  the page disagreeing with the session.

### Meeting Intelligence

- `004_meeting_intelligence.sql` — `meeting_facts`,
  `meeting_fact_participants`, `meeting_user_speakers`, and
  `meetings.intelligence_state` / `intelligence_error`.
- `app/services/intelligence.py` — windowed extraction over the approved
  transcript, validation, dedupe, embedding, and an atomic swap. Everything is
  extracted and embedded before the delete, so a failure keeps the old facts.
- Provenance and identity are enforced in the schema, not in Python:
  `CHECK (cardinality(source_segment_ids) > 0)`, and a composite FK to
  `speakers (id, meeting_id)` so a speaker from another meeting cannot be
  claimed.
- Extraction runs as a **second** background task after approval, so it only
  ever sees a meeting that reached `COMPLETED` and can never undo one.
- `PUT /api/meetings/{id}/me` sets which speaker the logged-in user is. The user
  comes from the session; no endpoint accepts a `user_id`.

### Retrieval

- `rag.plan` — one JSON call returning the standalone query, the fact types, the
  participant role, and whether the question is about the asker. Validated
  against enums, never interpolated into SQL, and any failure falls back to the
  question as typed.
- `rag.answer` now merges `intelligence.search` and `rag.search` under the same
  scope, facts first and sorted by meeting date so a "how did this change"
  question reads its evidence as a timeline.
- The rewritten query is used for retrieval only. The generator still receives
  the question exactly as typed.

### Removed

- `POST /api/chat`, the stateless single-meeting route. The meeting page links
  to `/chat?meeting_id=N`, which opens a scoped session, so nothing called it.
  Its two test assertions moved to routes the browser actually uses.
- `tests/test_chat.py`'s `approved` fixture, which duplicated what is now
  `conftest.make_meeting`.

## Temporal semantics: when a meeting happened, and what an unproven status is

### Goal

Fix three places where the previous wave presented a value the system happened
to have as one somebody had stated: `created_at` standing in for the meeting's
date, a bare `M월 D일` rolled forward a year, and `OPEN` used as the catch-all
for a status nobody gave. Source-first, before the NCP deployment.

### Completed

- **`meetings.held_at TIMESTAMPTZ NULL`** (`scripts/migrations/005_meeting_held_at.sql`).
  `intelligence.search` orders on `coalesce(held_at, created_at)` and
  `intelligence.build` resolves relative deadlines against it. The fallback is
  deterministic and labelled: `search` returns `meeting_at_known`, and every
  rendering of a fallback date carries `등록`, in the evidence block the model
  reads and on the chat source card.
- **`PUT /api/meetings/{id}/held-at`** plus a native `<input type="datetime-local">`
  on the meeting detail page. Editable at any status — it is metadata, not
  transcript text. The 2s poll does not overwrite the field while it has focus.
- **Deadline normalization tightened.** `deadline_at` is filled only for
  `오늘/내일/모레`, weekday forms, and year-bearing forms (`YYYY-MM-DD`,
  `YYYY년 M월 D일`). A bare `M월 D일` no longer resolves at all; the next-year
  rollover is gone. `deadline_text` is unchanged and always kept.
- **`UNKNOWN` fact status**, widened in the same migration and made the column
  default. No per-type default: an `ACTION_ITEM` with no stated status is
  `UNKNOWN` like everything else. The evidence renders it as
  `상태: 미확인(회의에서 완료 여부가 언급되지 않음)` and the system prompt
  forbids calling it either finished or outstanding.
- Migration `005` is the only file in the repository that drops anything — the
  anonymous `status` CHECK, re-added immediately accepting a superset. No row
  can fail the new constraint and no data is touched.

### Verified

- `.venv/bin/python -m pytest tests -q` — **157 passed, 0 failed, 0 skipped**
  (was 140). +14: held_at ordering vs. upload order, the labelled legacy
  fallback, `UNKNOWN` in the rendered evidence, the deadline table rewritten,
  explicit-status round trips, the `held-at` endpoint, the `005` upgrade path
  from a database holding real facts, and the `UNKNOWN` default at the DB level.
- Migration regression on throwaway schemas: fresh applies `001`–`005`; a
  database at `004` with a stored fact gains only `005` and keeps the row and
  its `OPEN` status; re-running applies nothing.
- `005` applied to the shared development database. Meetings 5, speakers 8,
  transcript_segments 174, chunks 36 — unchanged.
- `docker compose config --quiet` and `docker compose build` pass; the migration
  runs inside the image.

### Not verified

## ACTION_ITEM recall: a commitment the extraction never returned

### The report

A real NCP meeting, human UAT. The summary of the same approved transcript
listed two Action Items; Meeting Intelligence stored 요청 1 / 결정 0 / Action
Item 0. In the transcript:

    화자 B  비밀번호 만약에 현관 비밀번호 있으면 좀 저한테 남겨주시면 감사하겠습니다.
    화자 A  아, 네. 그 통화 종료하고 바로 문자로 남겨드리겠습니다.

The request was extracted. The acceptance that answers it was not.

### Root cause

**The extraction prompt. Not validation, dedupe, or windowing** — each was ruled
out by feeding the pipeline a response that contains the ACTION_ITEM and
watching it survive:

- `_validate` — 2 facts in, 2 out, roles and provenance intact
- `_dedupe` — the pair seen twice collapses to 2, not 1; and two facts of
  different types citing the *same* segments both survive, because the key is
  `(fact_type, sources)`
- `_windows` — 40 segments with 5 overlapping; two adjacent utterances always
  land in one window

So the model never emitted it. Two things in `EXTRACT_PROMPT` caused that:

1. `ACTION_ITEM: 누군가가 하기로 한 구체적인 업무` reads as third-person
   assignment — work handed to someone. The real utterance is a first-person
   promise, which the definition never names.
2. Nothing said a request and its acceptance are two facts. With nine
   prohibitions in a row led by "실제로 말하지 않은 업무를 만들지 마세요",
   recording the same exchange twice looks like the thing being forbidden. The
   model keeps one, and the request is the more literal match.

The summary prompt has neither problem: `Action Items` is a mandatory section it
must fill, and it never has to choose between two fact types.

### Fix

`EXTRACT_PROMPT` only. No schema change, no migration, no new fact type, no new
role, no dependency, no validator logic.

- `ACTION_ITEM` redefined as the speaker's own explicit promise or acceptance,
  with Korean commitment examples.
- The request/acceptance pair given as a worked example with **both** outputs,
  and an explicit "REQUEST와 ACTION_ITEM은 서로를 대체하지 않습니다".
- Non-examples named: plain agreement, past actions, possibilities, an
  unaccepted request.
- `ACTION_ITEM`'s `assignee_speaker_id` is the speaker of the promising
  utterance; a `REQUEST` only gets an assignee named inside the request itself.
- "하겠다고 약속한 것만으로는 상태가 정해지지 않습니다" — a promise is not a
  status. `UNKNOWN` semantics unchanged.

The summary is **not** wired into Meeting Intelligence. It found the gap; it is
not a data source. A human-readable generation has no provenance and must not
become structured truth.

### Verified

- `.venv/bin/python -m pytest tests -q` — **169 passed, 0 failed, 0 skipped**
  (was 157).
- The UAT exchange is now a fixture: both facts stored, `REQUESTER` = 화자 B on
  the request, `ASSIGNEE` = 화자 A on the action item, each citing only its own
  utterance, both `UNKNOWN`.
- Query regression with 화자 A mapped as the account: "내가 집 비밀번호를 어떻게
  전달하기로 했어?" reaches the model with the commitment utterance and without
  the 전화 distractor that is in the same transcript.
- `docker compose config --quiet` and `docker compose build` pass.

### Not verified

Recall itself. The local `OPENAI_API_KEY` returns 401 (`invalid_organization`),
so the live model was never called. The suite pins what the prompt instructs and
what the pipeline does with a given extraction — **not** that the model now
returns the ACTION_ITEM. That is the UAT step.

- Re-run [정보 재생성] on the meeting that failed and check 요청 ≥ 1 and
  Action Item ≥ 1, with the provenance pointing at 화자 A's own utterance.

## 제품 UI/UX 정리 + 회의 분류 (카테고리 · 필터 · 근거 밀도 · 업로드 회의 일시)

**목표.** React 전환 이후 남아 있던 "학생 프로젝트처럼 보이는" 구조를 실제 업무용 도구
수준으로 한 단계 정리하고, 회의가 늘어난 상황에서 관리 가능한 분류·검색 수단을 만든다.
프레임워크 교체가 아니고, 기존 AI/RAG/HITL/Meeting Intelligence semantics는 건드리지 않는다.

**완료 — 구조.**

- 사이드바가 두 겹이던 구조를 없앴다. `AppShell`이 `<aside>` 하나를 소유하고, route
  nav·채팅 목록(`/chat`에서만)·사용자 푸터를 담는다. `md` 아래에서는 같은 요소가 상단
  바가 되고 대화 목록은 버튼 하나로 접힌다. `SessionSidebar`(별도 패널)를 삭제하고
  `ChatNav`로 대체했다 — 세션 목록을 스스로 읽으므로 셸 안에 들어갈 수 있고, 화면
  크기별 복제 mount 없이 정확히 한 번만 mount된다.
- 대화 영역의 중심축을 `features/chat/canvas.ts:CANVAS`(max-w-3xl) 하나로 통일했다.
  검색 범위 바·질문·답변·근거·입력창이 모두 이 축을 쓴다. 입력창은 sticky이고 창 전체
  폭을 채우지 않는다.
- 회의 목록 필터 술어를 `lib/meetings.ts`(`matches`, `meetingTime`, `RANGES`)로
  한 곳에 모았다. 회의 목록 toolbar와 채팅 범위 대화상자가 같은 함수를 쓴다.
- `rounded-panel` 토큰을 없애고 radius를 `rounded`/`rounded-md`/`rounded-xl`(+배지
  pill)로 줄였다. 인사이트 종류 필터의 파란 primary 버튼을 조용한 selected surface로
  바꿨다. primary는 업로드·선택 완료·질문 보내기·요약 생성 등 실제 CTA에만 남았다.
- `Field`가 hint를 `<label>` 밖으로 내보내도록 고쳤다. 안에 있으면 hint 문장 전체가
  입력 필드의 accessible name이 된다.

**완료 — 근거 표시 밀도.**

실제 소스를 trace한 결과: `rag.answer`는 fact Top-K 6 + chunk Top-K 6, 생성 프롬프트에
검색된 전부, 응답 `sources[]`에 전부, `chat_messages.sources` JSONB에 전부. UI만
전부 펼치거나 전부 접는 토글이었다. **검색·생성·저장은 그대로 두고 화면만** 대표 근거
2개(`SourceList.HEAD`)를 펼쳐 두고 나머지를 `근거 N개 더 보기`로 접었다. 근거 카드도
큰 박스 대신 왼쪽 세로선 + 한 줄 메타(`[1] 회의명 · 날짜 · 시간 · 화자`)로 낮췄다.
유사도 점수는 계속 저장하고 계속 화면에 쓰지 않는다.

**완료 — 검색 범위 대화상자.**

`[] = GLOBAL` invariant를 그대로 두고, 그 두 상태를 `전체 회의` / `선택한 회의` 두 모드로
드러냈다. 체크는 모드 전환과 같은 의도로 취급하고, `선택한 회의`인데 아무것도 고르지
않으면 저장을 막는다. 검색 + 카테고리 + 기간 필터, 초기화, 회의별 카테고리·일시·상태
표시를 추가했다. ESC·✕·backdrop·취소·server-confirmed apply·실패 시 열린 채 유지는
그대로다.

**완료 — 회의 분류.**

- migration `006_meeting_categories.sql`: `meeting_categories`(`name UNIQUE`) 1개 테이블,
  `meetings.category_id` nullable FK `ON DELETE SET NULL`, 인덱스 1개. 추가만 한다.
- `GET/POST /api/meeting-categories`, `PATCH/DELETE /api/meeting-categories/{id}`,
  `PUT /api/meetings/{id}/category`. 목록과 상세 응답이 `category_id`·`category_name`을
  함께 내려주므로 화면이 join하지 않는다.
- 중복 이름은 `UNIQUE` 제약이 막고 `409`가 된다(선행 조회 없음). 카테고리 삭제는
  회의를 삭제하지 않고 미분류로 옮긴다 — FK가 하는 일이고, 삭제 전에 "회의 N개가
  미분류로 이동합니다"를 화면에 먼저 쓴다.
- 관리 화면은 만들지 않았다. 필터 옆 `카테고리 관리` 대화상자에서 생성·이름 변경·삭제를
  한다. 지정은 회의 상세의 `<select>` 하나.

**완료 — 회의 목록 / 업로드 회의 일시.**

- 검색(회의명·파일명) + 카테고리 + 상태 + 기간 + 정렬(회의 일시 최신/오래된, 등록 최신)을
  compact toolbar 하나로 묶고, 걸린 필터는 칩으로 보여주고 하나씩 또는 한 번에 푼다.
  "조건 때문에 0건"과 "아직 0건"을 다른 문구·다른 action으로 구분한다. 목록에서
  인사이트 상태 컬럼은 뺐다(상세에 그대로 있다).
- `POST /api/meetings`에 optional form field `held_at`을 추가했다. 업로드 대화상자가
  **브라우저 로컬 시각의 오늘**을 미리 채우고, 보내기 전에 바꾸거나 비울 수 있다.
  비우면 NULL, ISO8601이 아니면 `400`.
- **DB `DEFAULT now()`를 넣지 않았고, 기존 `held_at = NULL` 행을 backfill하지 않았다.**
  둘 다 migration 005가 없애려던 "업로드 시각을 회의 시각으로 단정한다"를 되살리는
  일이다. 실행 중 컨테이너에서 확인: 회의 6건 모두 `held_at = None`, `category_id = None`
  그대로.

## UI/UX 정리 2차 (근거 접힘 · 대화 이름 변경 · 카테고리 화면 분리 · 승인 전 안내)

**목표.** 앞선 wave가 남긴 어색함을 제품 수준으로 한 단계 더 정리한다. 근거가 답변을
덮는 문제, 질문·답변·근거·안내가 같은 톤으로 뭉쳐 보이는 문제, 대화 이름을 바꿀 수
없는 문제, 필터와 관리가 같은 무게로 놓인 문제, 승인 전 개요가 로딩 중인 것처럼
보이는 문제 — 다섯 개다. RAG·HITL·Meeting Intelligence semantics는 건드리지 않는다.

**완료한 것.**

- **근거는 기본 접힘.** `SourceList`가 `근거 N개 보기` 한 줄만 남기고, 펼치면 검색된
  전부를 원문 그대로 보여준다(line clamp 제거 — 확인하려고 펼친 인용을 자르는 것은
  모순). `HEAD = 2` 상수는 사라졌다. `app/services/` 무수정: 검색 Top-K, 생성 context,
  응답 `sources[]`, `chat_messages.sources` 전부 그대로.
- **채팅 4블록 분리.** 질문은 우측 정렬 버블, 답변은 카드 없는 본문(15px/1.75),
  근거는 테두리 있는 secondary 블록, 그리고 백엔드가 직접 쓰는 두 답변
  (`rag.NO_ANSWER`, `rag.NO_IDENTITY`)은 `lib/labels.ts:isNoticeAnswer`로 골라 notice로
  렌더한다 — 회의에서 나온 사실이 아니라 검색에 대한 안내이기 때문이다.
- **대화 이름 변경.** `PATCH /api/chat/sessions/{id}/title` 추가(trim, 40자 절단, 공백
  400, 소유권 404). 사이드바 행의 kebab 메뉴 → `이름 변경` / `삭제`, 이름은 행 안에서
  인라인 편집(Enter 저장 / Esc 취소 / 빈 이름 저장 불가). 자동 제목은 제목이 아직
  기본값 `새 채팅`일 때만 동작하므로 신규 컬럼 없이 "사람이 정한 이름은 안 덮는다"가
  보장된다.
- **회의 목록 툴바 압축.** 검색은 `sm:w-72` 고정, 카테고리·상태·기간은 `h-8` auto-width
  select, 정렬은 `ml-auto`로 우측 분리(정렬은 목록의 내용이 아니라 순서를 바꾸므로
  필터가 아니다). 활성 필터 칩과 `필터 초기화`는 유지.
- **카테고리 관리를 `/categories`로 분리.** `CategoryDialog.tsx` 삭제. 새 화면은 생성
  input + 행별 인라인 rename + 삭제 확인 + `회의 N개` + 빈 상태 + 회의 목록으로 돌아가는
  링크. 회의 목록에는 표 아래 조용한 텍스트 링크만 둔다 — 관리는 탐색보다 한 단계
  아래다.
- **승인 전 안내 상태.** `features/meetings/PendingNotice.tsx` 하나가 상태 badge + 왜
  비어 있는지 + 다음 사람 행동(`회의록 검토 → 저장 → 승인`)을 말하고, 개요와 인사이트
  탭이 같이 쓴다. 개요의 skeleton은 제거했다 — 아무것도 로딩되고 있지 않았고, 승인은
  자동으로 오지 않는다. 초안 요약이나 임시 fact는 만들지 않는다.
- **시각 정리.** `--shadow-panel` 토큰 1단(페이지 배경 위 surface에만), Panel·표에 적용.
  `rounded` → `rounded-md` 통일. 요약 패널의 죽은 `!approved` 분기 삭제.
  `/categories` 화면의 중복 toast 제거(인라인 오류와 이중 표시였음).

**신규 패키지.** `@radix-ui/react-dropdown-menu` 1개. kebab 메뉴의 `aria-haspopup`,
방향키 roving focus, Escape, outside click, trigger로 focus 복귀를 직접 구현하는 것보다
적은 코드다. `components/ui/Menu.tsx`에 한 번만 감싸 두었다.

**검증.**

- backend `pytest tests -q` — **200 passed / 0 failed / 0 skipped** (이전 194).
  `tests/test_chat.py` +6(이름 변경 성공·trim·공백 400·40자 절단·자동 제목 미덮음·
  타 사용자 404·익명 401).
- frontend `npm test` — **Vitest 92 passed / 0 failed** (이전 82). `npm run typecheck`,
  `npm run lint` 통과. `npm run build` 성공(JS 466.27 kB, CSS 28.69 kB).
- `npm run e2e` — **Playwright 12 passed** (이전 9). 신규 3건: 근거 접힘→펼침→재접힘,
  세션 이름 변경 후 새로고침 유지, `/categories` 진입·생성·삭제. 1024 viewport 검사에
