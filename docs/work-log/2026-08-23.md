# 2026-08-23

## Goal

Close the eight problems the real-meeting UAT left open, without changing what
the search or the provenance rules mean:

1. A general question ("이 통화에서 결정된 내용 정리해줘.") was intermittently
   refused with "[나로 지정]을 먼저 눌러 주세요", and answered normally when
   asked again.
2. The chat called its evidence 근거 and printed all of it under the answer.
3. Question and answer were hard to tell apart in a long conversation.
4. The meeting list had no pagination.
5. The meeting filters each took a full row.
6. Categories were flat labels.
7. A meeting could not be deleted before it was indexed.
8. A meeting left at 화자 분리 중 by a server restart could not be deleted at
   all.

## Completed

### Self-scoped questions are decided deterministically

- `rag.is_self_scoped(question)` — explicit first-person surface forms
  (`rag.SELF_FORMS`) matched with a `(?<![가-힣])` lookbehind, so 내용 / 안내 /
  결제 / 정리 are not first person. This is now the only thing that can require a
  user↔speaker mapping.
- `self_reference` was removed from `PLAN_PROMPT` and from the planner's parsed
  output. Nothing reads the model's opinion of it any more; the planner still
  rewrites the query and names fact types and roles.
- Real self-scoped questions are unchanged: "내가 요청한 게 뭐야?" with no
  mapping still answers `rag.NO_IDENTITY`, and still searches facts only.
- The root cause of the flapping was that one nondeterministic bit gated whether
  the corpus was searched at all.

### 출처 panel

- `features/chat/SourceDrawer.tsx` replaces `SourceList.tsx`: a control reading
  `출처 N개`, a `Citation` button per `[N]` in the answer, and a panel beside the
  conversation (a full-width sheet below `md`) listing every retrieved source.
  Clicking `[3]` opens the panel with that source selected and scrolled to.
- Each card carries the citation number, the meeting (linked), its date, the
  time range, the speakers, the structured fields for a fact, the verbatim
  transcript text, and a link to the position in the transcript
  (`?tab=transcript&at=<seconds>`), which `TranscriptPanel` highlights.
- Nothing about grounding changed: same rows from `rag.serialize_sources`, same
  `source_segment_ids`, same `chat_messages.sources`. 출처 is user-facing copy
  only — the `[근거]` prompt block, `serialize_sources`, and the stored JSONB keep
  their names. Scores, chunk ids, and fact ids stay in the payload and off the
  screen.

### Question / answer separation

- A question is a right-aligned tinted bubble with extra space above it; an
  answer is a left-aligned bordered surface that ends where its 출처 control
  does. No nested cards were added, and the notice shape for
  `rag.NO_ANSWER` / `rag.NO_IDENTITY` is unchanged.

### Meeting list: server-side narrowing, paging, and sort

- `GET /api/meetings` takes `page`, `page_size` (1–100, default 20), `q`,
  `category`, `status`, `days`, `sort`, and returns
  `{items, total, page, page_size}`. `meetings._narrow` builds the predicate
  once; the `COUNT` and the page query share it, so the total always describes
  the same set as the rows. `sort` and `status` are whitelists.
- The page's whole query state lives in URL search parameters, because two things
  write it: the toolbar and the new sidebar category tree. A filter change
  returns to page 1; a page change keeps the filters. No store was added.
- `Pager` shows `총 N개 중 x–y`, a 20/50/100 page size, and prev/next. A page
  past the end still reports the real total.
- The filter bar's real bug was CSS, not layout: `controls.tsx` had `w-full` in
  its base class, and Tailwind emits `.w-full` after `.w-auto` and after every
  fixed width, so every `w-56` / `w-auto` on a field was silently overridden and
  each select filled a row. The base class no longer sets a width; each caller
  says `w-full`, a fixed width, or `flex-1`.

### Category hierarchy

- Migration `008_category_hierarchy.sql`: `parent_id` self-reference with
  `ON DELETE RESTRICT`, `CHECK (parent_id IS DISTINCT FROM id)`, and an index.
  Additive — every existing category stays a root, no row moves, no name changes.
- `categories.SUBTREE` (recursive CTE) is the one definition of "this category
  and everything under it": the meeting list's category filter and the
  move-cycle check both use it. `categories.TREE` returns `path`, `depth`, and
  the direct meeting and child counts in path order.
- `POST` takes an optional `parent_id`; `PUT /{id}/parent` moves a category
  (self and descendants refused, `400`); `DELETE` refuses a category with
  children (`409`) rather than cascading, and its meetings still go to 미분류 by
  `ON DELETE SET NULL`.
- `features/meetings/CategoryNav.tsx` renders the tree in the app's one sidebar,
  in the slot `ChatNav` uses on the chat route — 전체 회의 / 미분류 / the tree,
  collapsible, each row a link that writes `?category=`. `/categories` gained
  parent selection on create, an in-row move, and a delete dialog that names the
  children in the way. Every category `<select>` now shows the path.
- A meeting still has exactly one `category_id`, and moving a category moves no
  meeting.

### Deletion

- `DELETE /api/meetings/{id}` has no status gate: `UPLOADED`, `TRANSCRIBING`,
  `DIARIZING`, `REVIEW_REQUIRED`, `INDEXING`, `COMPLETED`, `FAILED` all delete.
  One endpoint for every screen; the UI decides where to offer it.
- The pipeline cooperates instead of the API refusing. `pipeline.set_status`
  reports whether the row still exists, `process` checks before persisting a
  transcript, and `_abandon` removes the audio it was holding — the one thing a
  foreign key cannot clean up. `index_transcript` checks before its write so a
  deliberate delete is not logged as an indexing failure.
- The detail page's 관리 panel is always present now; for an unsettled meeting it
  says the analysis may no longer be running, and the confirm dialog says the
  task will finish having stored nothing. The meeting list gained a row menu with
  삭제 (the row is a link, so the menu stops the click).
- Nothing cancels a running STT or diarization. That was deliberate, and is
  recorded as a limitation.
