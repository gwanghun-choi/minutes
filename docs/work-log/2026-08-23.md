# 2026-08-23

## Goal

Close the eight problems the real-meeting UAT left open, without changing what
the search or the provenance rules mean:

1. A general question ("이 통화에서 결정된 내용 정리해줘.") was intermittently
   refused with "[나로 지정]을 먼저 눌러 주세요", and answered normally when
   asked again.
2. The chat called its evidence 근거 and printed all of it under the answer.
3. Question and answer were hard to tell apart in a long conversation.
4. The meeting list had no pagination.
5. The meeting filters each took a full row.
6. Categories were flat labels.
7. A meeting could not be deleted before it was indexed.
8. A meeting left at 화자 분리 중 by a server restart could not be deleted at
   all.

## Completed

### Self-scoped questions are decided deterministically

- `rag.is_self_scoped(question)` — explicit first-person surface forms
  (`rag.SELF_FORMS`) matched with a `(?<![가-힣])` lookbehind, so 내용 / 안내 /
  결제 / 정리 are not first person. This is now the only thing that can require a
  user↔speaker mapping.
- `self_reference` was removed from `PLAN_PROMPT` and from the planner's parsed
  output. Nothing reads the model's opinion of it any more; the planner still
  rewrites the query and names fact types and roles.
- Real self-scoped questions are unchanged: "내가 요청한 게 뭐야?" with no
  mapping still answers `rag.NO_IDENTITY`, and still searches facts only.
- The root cause of the flapping was that one nondeterministic bit gated whether
  the corpus was searched at all.

### 출처 panel

- `features/chat/SourceDrawer.tsx` replaces `SourceList.tsx`: a control reading
  `출처 N개`, a `Citation` button per `[N]` in the answer, and a panel beside the
  conversation (a full-width sheet below `md`) listing every retrieved source.
  Clicking `[3]` opens the panel with that source selected and scrolled to.
- Each card carries the citation number, the meeting (linked), its date, the
  time range, the speakers, the structured fields for a fact, the verbatim
  transcript text, and a link to the position in the transcript
  (`?tab=transcript&at=<seconds>`), which `TranscriptPanel` highlights.
- Nothing about grounding changed: same rows from `rag.serialize_sources`, same
  `source_segment_ids`, same `chat_messages.sources`. 출처 is user-facing copy
  only — the `[근거]` prompt block, `serialize_sources`, and the stored JSONB keep
  their names. Scores, chunk ids, and fact ids stay in the payload and off the
  screen.

### Question / answer separation

- A question is a right-aligned tinted bubble with extra space above it; an
  answer is a left-aligned bordered surface that ends where its 출처 control
  does. No nested cards were added, and the notice shape for
  `rag.NO_ANSWER` / `rag.NO_IDENTITY` is unchanged.

### Meeting list: server-side narrowing, paging, and sort

- `GET /api/meetings` takes `page`, `page_size` (1–100, default 20), `q`,
  `category`, `status`, `days`, `sort`, and returns
  `{items, total, page, page_size}`. `meetings._narrow` builds the predicate
  once; the `COUNT` and the page query share it, so the total always describes
  the same set as the rows. `sort` and `status` are whitelists.
- The page's whole query state lives in URL search parameters, because two things
  write it: the toolbar and the new sidebar category tree. A filter change
  returns to page 1; a page change keeps the filters. No store was added.
- `Pager` shows `총 N개 중 x–y`, a 20/50/100 page size, and prev/next. A page
  past the end still reports the real total.
- The filter bar's real bug was CSS, not layout: `controls.tsx` had `w-full` in
  its base class, and Tailwind emits `.w-full` after `.w-auto` and after every
  fixed width, so every `w-56` / `w-auto` on a field was silently overridden and
  each select filled a row. The base class no longer sets a width; each caller
  says `w-full`, a fixed width, or `flex-1`.

### Category hierarchy

- Migration `008_category_hierarchy.sql`: `parent_id` self-reference with
  `ON DELETE RESTRICT`, `CHECK (parent_id IS DISTINCT FROM id)`, and an index.
  Additive — every existing category stays a root, no row moves, no name changes.
- `categories.SUBTREE` (recursive CTE) is the one definition of "this category
  and everything under it": the meeting list's category filter and the
  move-cycle check both use it. `categories.TREE` returns `path`, `depth`, and
  the direct meeting and child counts in path order.
- `POST` takes an optional `parent_id`; `PUT /{id}/parent` moves a category
  (self and descendants refused, `400`); `DELETE` refuses a category with
  children (`409`) rather than cascading, and its meetings still go to 미분류 by
  `ON DELETE SET NULL`.
- `features/meetings/CategoryNav.tsx` renders the tree in the app's one sidebar,
  in the slot `ChatNav` uses on the chat route — 전체 회의 / 미분류 / the tree,
  collapsible, each row a link that writes `?category=`. `/categories` gained
  parent selection on create, an in-row move, and a delete dialog that names the
  children in the way. Every category `<select>` now shows the path.
- A meeting still has exactly one `category_id`, and moving a category moves no
  meeting.

### Deletion

- `DELETE /api/meetings/{id}` has no status gate: `UPLOADED`, `TRANSCRIBING`,
  `DIARIZING`, `REVIEW_REQUIRED`, `INDEXING`, `COMPLETED`, `FAILED` all delete.
  One endpoint for every screen; the UI decides where to offer it.
- The pipeline cooperates instead of the API refusing. `pipeline.set_status`
  reports whether the row still exists, `process` checks before persisting a
  transcript, and `_abandon` removes the audio it was holding — the one thing a
  foreign key cannot clean up. `index_transcript` checks before its write so a
  deliberate delete is not logged as an indexing failure.
- The detail page's 관리 panel is always present now; for an unsettled meeting it
  says the analysis may no longer be running, and the confirm dialog says the
  task will finish having stored nothing. The meeting list gained a row menu with
  삭제 (the row is a link, so the menu stops the click).
- Nothing cancels a running STT or diarization. That was deliberate, and is
  recorded as a limitation.

# 2026-08-23 (wave 2) — ownership, sharing, versioning

## Goal

Turn meetings from installation-wide data into owned assets, and make an
approved transcript correctable without taking it out of search. Three asks, one
model, because they all turn on the same missing fact:

1. audio / meeting / analysis / retrieval isolated per logged-in account;
2. an indexed meeting shareable by invitation, with accept, reject, and revoke;
3. a `COMPLETED` meeting revisable — new version, re-index, atomic switch.

Verifiable goal: two real accounts, and every door (list, detail, transcript,
status, summary, facts, versions, shares, and all four retrieval paths) answers
the same way about the same meeting.

## Completed

### One access predicate

- `app/services/access.py` — `READABLE` as SQL over a `meetings m` alias, plus
  `role()`, `require_read()`, `require_owner()`, `visible()`. Two roles, no
  matrix. Pasted by the meeting list, the detail page, the category counts, and
  all four retrieval paths.
- 404 for a meeting the account may not read, at every endpoint, identical to an
  id that was never issued. 403 only where the caller already knows it exists.
- `rag.search*` and `intelligence.search*` take `user_id`; `None` is the
  evaluation harness on its own schema and is the only caller that passes it.

### Ownership

- Migration 009 adds `meetings.owner_user_id` (nullable, `ON DELETE SET NULL`).
  Backfill is evidence-only: the single account that claimed a speaker in that
  meeting, or the single active account in a one-account database. Anything else
  stays NULL, and a NULL owner is readable by nobody.
- The owner comes from `request.state.user` on upload. No endpoint accepts one.

### Sharing

- `meeting_shares`, one row per (meeting, invited account), PENDING → ACCEPTED /
  REJECTED, and → REVOKED with `revoked_at`. `UNIQUE` refuses a duplicate and a
  `CHECK` refuses inviting yourself — both in the database.
- `app/api/shares.py` (owner side + invitation inbox), `app/api/users.py` (the
  invite picker's search — a search, never a browse).
- Revocation is immediate at all six doors because nothing caches the predicate.
  Stored evidence on old messages is filtered on read: the `[N]` stays, the text,
  the meeting, and the link go.

### Versioning

- `meeting_versions` (DRAFT → INDEXING → PUBLISHED → SUPERSEDED) plus a `version`
  column on `transcript_segments`, `chunks`, and `meeting_facts`. Two partial
  unique indexes carry "one published" and "one open".
- `app/services/versions.py`; `pipeline.index_transcript` now indexes one named
  version and publishes it *inside the same transaction that replaces the
  chunks*, with embedding done before that transaction opens.
- `meetings.status` stays `COMPLETED` for the whole revision, deliberately: it is
  a retrieval predicate, so moving it would take the published version out of
  search for exactly the window this design exists to remove.
- `POST /approve` publishes both the first draft and every later revision.

### UI

- 내 회의 / 공유받은 회의 tabs (`?scope=`), owner column, row menu only for an
  owner.
- Meeting detail: version panel (history + 회의록 수정 / 수정 취소), sharing
  panel (owner only), read-only metadata for a shared reader, and a transcript
  notice that says which version search is using while a draft is open.
- `/invitations` inbox with a pending count in the sidebar.
- Chat scope dialog grouped into 내 회의 / 공유받은 회의 with per-group select-all.
- A revoked source renders as a citation with no excerpt and says why.

### Test accounts

- Migration 010 seeds `user2` the way 003 seeded `user`: precomputed scrypt hash,
  `WHERE NOT EXISTS`, no plaintext anywhere. Ownership and sharing cannot be
  exercised with one account.

## Verification

- `pytest tests -q` — 417 passed, 1 failed. The failure is
  `test_deleting_a_parent_is_restricted_by_the_foreign_key`, and it is an
  environment artifact, not a regression: PostgreSQL 18 reports SQLSTATE 23001
  (`RestrictViolation`) for an `ON DELETE RESTRICT` violation where earlier
  versions reported 23503 (`ForeignKeyViolation`), which is what the test
  asserts. It fails identically on the unmodified tree. Left unchanged.
- 65 new backend tests: `tests/test_ownership.py` (53),
  `tests/test_sharing.py` (39), `tests/test_versions.py` (23) — plus 12 new
  migration tests covering the 009 upgrade path on a database that already holds
  meetings, users, transcripts, chunks, and embeddings.
- A live two-user run against the real database as `user` and `user2`: 66/66
  checks, covering the whole invite → accept → RAG → revoke → version flow.
- Frontend: `npm run typecheck`, `npm run lint`, `npm test` (150 passed),
  `npm run build`, `npx playwright test` (16 passed).

## Blockers

- `docker compose config` / `docker compose build` were not run: Docker is not
  installed in this environment. Nothing in the Dockerfile or compose.yaml
  changed, and `npm run build` — the only build input this wave touched — passes.
- The shared NCP database was not reachable, so the migration was verified
  against a local PostgreSQL 18 + pgvector 0.8.1, including the upgrade path from
  a schema built out of migrations 001–008 with data in it.

# 2026-08-23 (wave 3) — the compose network matches the deployment

## Goal

`docker compose run --rm minutes python -m scripts.migrate` failed on the server
with `Temporary failure in name resolution` while the already-running container
talked to the database fine. Make the repository describe the deployment that is
actually running, so a clone reproduces it without a hand-attached network.

## Completed

- **Root cause.** `compose.yaml` declared no `networks:`, so Compose created an
  implicit `minutes_default` per project. The long-running `minutes` container
  was on `minutes-net` only because someone had attached it outside this file; a
  one-off `run` container got `minutes_default` and could not resolve
  `minutes-postgres`. `docker run --network minutes-net` on the same image
  resolved it to `172.18.0.2` and reached 5432, which is what ruled out the
  database, the image, and the migration.
- **`compose.yaml`** now overrides the project default:
  `networks.default → {external: true, name: minutes-net}`. Overriding `default`
  rather than adding a per-service network is what makes `run` containers get it
  too, which is the case that broke.
- **`.env.example`** described the retired company instance (`didim_api`, empty
  host). Corrected to `DATABASE_HOST=minutes-postgres` / `DATABASE_NAME=minutes`,
  with a note on why the host is a container name. No secret values.
- **Docs.** README's Docker section now starts from creating the network
  (idempotent one-liner) and explains the failure mode by name;
  `docs/architecture/current.md` gained a "The network" subsection under
  Deployment shape; `AGENTS.md` and `CLAUDE.md` gained the invariant.
- **`app/config.py`** fell back to `DATABASE_NAME=didim_api` when the variable
  was unset — the last reference in code to the retired company instance. It is
  `minutes` now. `.env` always sets the variable, so nothing observable changes;
  what changes is where an unset variable points, and it should not be a
  database that no longer exists. No test pinned the old default. The two README
  lines and the `AGENTS.md` line that still described that instance as the
  current one were corrected with it; the work-log entries that mention it are
  history and were left alone.

# 2026-08-23 (wave 4) — immutable minutes, personal filing, and the chat surfaces

## Goal

Turn what the human UAT settled into the source: approved minutes stop being
editable, filing stops being a property of the meeting, and the three chat/list
surfaces the UAT complained about (invitation page, category page, source panel)
match what the data actually means.

## Completed

- **Approved minutes are immutable.** `meetings._editable_draft` now opens only
  for a `DRAFT` on a `REVIEW_REQUIRED` meeting, and it is the single gate in
  front of the transcript PATCH, the speaker rename, the correction suggestions,
  and the approval. `POST`/`DELETE` on `/versions` are gone (`405`), along with
  `versions.create_draft` / `discard`. `meeting_versions` and the per-version
  transcript stay as read-only provenance, because a database that ran the
  previous build may hold a v2 an old citation rests on — and a stranded `DRAFT`
  from it cannot be resumed or approved.
- **Filing became personal** (migration 011). `user_categories` is one tree per
  account, `user_meeting_filing` is `(user_id, meeting_id) → category_id, alias`,
  and `chat_sessions.category_id` files a conversation in the same tree. Every
  category reference is a composite FK carrying `user_id`, so the database
  refuses a cross-account filing. `PUT /category` and the new `PUT /alias` take
  **read** access: a shared reader arranges their own screen and the owner's does
  not move. `display_title = coalesce(alias, title)` is resolved per request and
  stored chat evidence is retitled on read.
- **Organisation is not permission.** `organization.FILING` is a LEFT JOIN;
  after a revoke the reader's filing survives, the folder counts zero, and every
  door still answers 404. Tested explicitly.
- **Backfill.** 011 moves each owner's `meetings.category_id` into their own
  tree, ancestors included; another account gets nothing and an orphan is
  skipped. `meeting_categories` / `meetings.category_id` are left in place,
  unread, documented as legacy.
- **Three routes removed.** Category CRUD moved into the sidebar tree (`[+]`, a
  `⋯` per row, recent meetings + 전체 보기 when expanded); an invitation became a
  count in the sidebar plus a dialog; the version panel went with the workflow.
  `/categories`, `/invitations`, `CategoriesPage`, `InvitationsPage`,
  `VersionPanel`, `useVersionMutations`, and `ageBucket` are gone.
- **Chat surfaces.** An answer is prose rather than a full-width card; the
  question keeps a compact bubble. The 출처 drawer is always mounted and moves by
  `translate-x` — overlay, not push, `inert` + `aria-hidden` when closed, toggle
  button, `[N]` focuses a card, ESC closes. The button's count is what the answer
  **cited**; the drawer still holds every candidate and says how many were not
  quoted.
- **Docs.** `AGENTS.md` traded its version invariant for an immutability
  invariant and a personal-organisation invariant; `CLAUDE.md`, `README.md`, and
  `docs/architecture/current.md` follow.
